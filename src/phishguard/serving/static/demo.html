PhishGuard

URL model v0.2

Paste a link and get a calibrated probability that it is phishing. The model reads the URL string only. It never visits the page.

Nothing is fetched or opened. Scoring takes a few milliseconds once the service is awake.

Try:

The score, the verdict at the served threshold, and where the score sits against the measured reference points appear here.

What the number is

A LightGBM model over 41 numeric features of the URL string plus its TLD, exported to ONNX and run in ONNX Runtime, with an isotonic calibrator on top, fit on the validation split so scores track observed phishing rates. The calibrated Brier score on the test split is 0.0157; per-bin reliability has not been plotted yet.

It sees the URL and nothing else. A clean-looking URL on a compromised site scores clean, and a legitimate site with an odd hostname can score high.

Why the first model could not be trusted

The public dataset (PhiUSIIL, about 235,000 URLs) gives a URL model an AUC above 0.99 almost for free. Three shortcuts made that number worthless, each caught by hand-written smoke tests:

  1. The labels were upside down. Raw label=1 means legitimate. Obvious phishing URLs scored 0.0 until the polarity was fixed and locked by a test.
  2. Every legitimate URL started with https://www. and none had a path. The model learned "has www". URLs are now canonicalized the same way at training and serving time.
  3. has_https carried 47.6% of the model's gain before those fixes and 34.9% after. This model drops it and the length features. The top feature is now subdomain_depth at 27.2% of gain, and a test fails the build if any single feature passes 50%.

Limits

URL only. The HTML and screenshot models are scaffolded but not trained, because there is no labeled multimodal corpus yet. The served threshold is 0.50; the headline false-positive rate in the README is quoted at 0.70.

Submitted URLs are logged inside this container for drift monitoring. Only a redacted copy is stored: any user:password@ part and credential-like parameters (tokens, keys, codes, signatures) are removed first. The log is not published and is wiped when the container restarts.
